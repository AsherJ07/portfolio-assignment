# Rules Evolution

## 2026-11-08 - Public documentation standard

**Change:** Added a rule requiring the README and repository landing experience to read as public, employer-ready documentation, while routing detailed status history to the appropriate evidence files.

**Why:** The student identified that the README exposed internal completion language such as pending verification and linked directly to the rubric audit as a status disclaimer. That wording was useful during development but unprofessional as the repository's public introduction.

**Evidence:** The student's final documentation review explicitly distinguished public-facing project presentation from the assignment's internal audit trail. The rule preserves required plans, prompts, tests, and audit evidence while preventing stale internal notes from dominating the repository landing page.
